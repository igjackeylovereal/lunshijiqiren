IP 由 DHCP 分配，换 AP 就会变（见过 `10.224.117.14`、`10.109.40.14`、`10.166.34.14`）。

```powershell
# 笔记本上
ipconfig | findstr IPv4          # 看自己在哪个网段
ping reinovo.local               # mDNS 优先
nmap -p 22 10.166.34.0/24        # 扫 22 端口
```

```bash
# 机器人屏幕/键盘上
hostname -I
```

### 1.2 SSH

```powershell
ssh bobac2@10.166.34.14
# 首次连接输入 yes，密码 root
```

常见错误：

| 现象 | 原因 | 处理 |
|---|---|---|
| `Permission denied` | 用了 root 账号 | 必须 `bobac2` |
| `Connection timed out` | 不在同网段 / 机器人关机 | `ping` 确认 |
| `Host key verification failed` | 换 IP 后密钥不符 | `ssh-keygen -R <IP>` |
| SSH 端口通但读不到 banner | 机器人掉线，中间设备假连通 | 重启机器人网络/等它回来 |

## 3. 启停：只用 ctl，不要手工起 app

```bash
# 状态（先看这个）
bash ~/bobac_practicum_ctl.sh status

# 导航模式（可带地图与初始位姿）
bash ~/bobac_practicum_ctl.sh up nav
bash ~/bobac_practicum_ctl.sh up nav /home/bobac2/bobac_practicum_run/maps/classroom_navigation_20261105_094756.yaml -1.76728869346 -2.81884047614 -1.53206144219

# 建图模式（gmapping + 键盘遥控页面）
bash ~/bobac_practicum_ctl.sh up mapping

# 静态联调（不动机器人）
bash ~/bobac_practicum_ctl.sh up static

# 全部停止
bash ~/bobac_practicum_ctl.sh stop

# 其它
bash ~/bobac_practicum_ctl.sh maps        # 列出地图
bash ~/bobac_practicum_ctl.sh save-map    # 保存当前建图
bash ~/bobac_practicum_ctl.sh log         # 查看日志
```

### 3.1 初始位姿的优先级

```
① up nav <map> <x> <y> <yaw>    → 用命令行的值，并写回 last_pose.txt
② up nav <map>                  → 读 last_pose.txt，原样保留
③ 文件不存在                     → 用 0 0 0 并写入
```

当前固定初始位姿：

```
-1.76728869346  -2.81884047614  -1.53206144219      # x, y, yaw(rad)
```

**注意**：网页上「设初始位姿」只发 `/initialpose` 给 AMCL，**不会**写 `last_pose.txt`，重启后回到文件里的值。

### 3.2 为什么不能手工 `setsid python app.py`

`ctl` 保证顺序：roscore → launch（雷达/底盘/odom/map/amcl/move_base）→ app。
手工另起 app 一旦赶上 master 重启，会出现：

- 端口被占用（`Address already in use`），新进程起不来
- `rosnode list` 里没有 `/bobac_practicum`，应用收不到 `/scan`、`/odom`
- 表现：页面打开正常，但一直报“雷达、里程计或定位尚未就绪”

## 4. 网页访问：必须走 SSH 隧道

网页只监听**机器人本机回环**：

```
http://127.0.0.1:8765        只绑 127.0.0.1，外部无法直连
并且校验 Host: 127.0.0.1:8765
```

所以笔记本上必须建隧道，且**本地端口必须是 8765**：

```powershell
ssh -L 8765:127.0.0.1:8765 -N bobac2@10.166.34.14
# 这个窗口不能关
```

然后浏览器打开 <http://127.0.0.1:8765/>。

### 4.1 隧道断了的特征

```powershell
curl.exe -v http://127.0.0.1:8765/
```

| 输出 | 含义 | 处理 |
|---|---|---|
| `WinError 10054` / `Connection reset` | 隧道通道失效（机器人重启/换网最常见） | 杀掉占用 8765 的进程，重建隧道 |
| `HTTP/1.1 200` | 应用正常 | 刷新浏览器 |
| `Connection refused` | 隧道没起 | 重建隧道 |

```powershell
# 杀占用 8765 的进程
Get-NetTCPConnection -LocalPort 8765 -State Listen | ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }

# 重建（本仓库 tools/laptop/tunnel_now.py 就是这个）
D:\课设\console\.venv\Scripts\python.exe D:\课设\console\tunnel_now.py
```

## 5. 改代码与部署

### 5.1 部署流程（务必照做）

```bash
# 机器人上：先备份
cd /home/bobac2/bobac_practicum_ws/src/bobac_practicum
cp scripts/app.py scripts/app.py.bak_$(date +%Y%m%d_%H%M%S)

# 笔记本：上传
scp app.py bobac2@10.166.34.14:/home/bobac2/bobac_practicum_ws/src/bobac_practicum/scripts/

# 机器人：重启（用 ctl，别手工）
bash ~/bobac_practicum_ctl.sh stop
bash ~/bobac_practicum_ctl.sh up nav
```

Python 脚本改完**不需要** `catkin_make`；launch 文件在下次启动时生效。

### 5.2 Python 2.7 注意

- 不要 f-string、不要 `subprocess.run`、不要 `exist_ok=`
- 中文写入 JSON 用 `json.dumps(..., ensure_ascii=True)` 或 `.encode('utf-8')`
- 写文件用「临时文件 + rename」原子替换，避免写坏配置

### 5.3 配置文件

`~/bobac_practicum_run/navigation_project_20261105.json`：

```json
{
  "places": [
    {"id": "classroom", "name": "教室", "aliases": ["教室"],
     "pose": {"x": -0.67, "y": -4.57, "yaw": 0.0},
     "map_id": "008f86..."}
  ],
  "map_frame": "map",
  "base_frame": "base_footprint",
  ...
}
```

- `places[].pose = null` 表示**未标定**，语音“去教室”会拒绝
- `map_id` 必须与当前地图一致，否则导航拒绝
- 改坏了用同目录 `*.bak_*` 恢复

## 8. 故障对照表（都是本机真实踩过的）

| 报错/现象 | 根因 | 处理 |
|---|---|---|
| `导航未启动：雷达、里程计或定位尚未就绪` | `health` 三项有一项 false；多数是 `localized` | 查 `/amcl_pose`、`tf map→base`；见 §9 |
| `导航未启动：导航 Action 不可用` | move_base 代价地图在等 `map` 坐标系（AMCL 没发 map→odom） | 先修定位；`rostopic list \| grep move_base` 确认 |
| 页面打不开，日志却写 `HTTP ready ... simulated=False` | 隧道断（应用本身正常） | 重建隧道，见 §4.1 |
| 日志 `Address already in use` | 端口被旧 app 占用 | 结束旧进程，用 `ctl` 重启 |
| `rosnode list` 没有 `/bobac_practicum` | app 与 master 断连（手工启动顺序错误） | `ctl stop && ctl up nav` |
| AMCL 一直 `Dropped 100.00%` | TF 在扫描时刻查不到（常见：TF 时间戳被改成未来） | 确认 `wheel_odometry` 用 `stamp` 原值广播 |
| 车静止时定位过 2 秒失效 | AMCL 阈值 `update_min_d=0.25`、`update_min_a=0.2` 不满足就不更新 | 已固化 `update_min_d/a=0`（§9） |
| `place pose = null`，语音拒绝 | 地点未标定 | 网页「设定地点」重新点选，或「记录当前实际位置」 |
| TEB 报 `max_vel_x <= penalty_epsilon` | 参数不合理，规划失败 | `penalty_epsilon=0.02` |
| 配置文件变成几十字节 | 用 `open(...,'w')` 中途抛异常截断 | 从 `*.bak_*` 恢复，改写用临时文件+rename |

## 9. 定位相关的当前状态（2026-11-19）

已做的修改：

```text
① navigation.launch 增加：
     /amcl/update_min_d        = 0.0
     /amcl/update_min_a        = 0.0
     /amcl/transform_tolerance = 1.0
   目的：车静止时也让 AMCL 每帧更新，持续发布 /amcl_pose 与 map→odom

② wheel_odometry.py 的 TF 超前补偿（+0.3 s）已回退
   原因：它让 TF 缓冲“最早数据在未来”，任何按激光时刻的查询都报
         extrapolation into the past，AMCL/gmapping 全部丢帧
```

验证方法（机器人恢复在线后）：

```bash
rostopic hz /amcl_pose                    # ≥2 Hz
rosrun tf tf_echo /map /base_footprint    # 输出时间戳跟手
curl -s http://127.0.0.1:8765/api/status  # health.localized = true
```

## 10. 安全须知

1. 导航模式下，**确认目标就会动车**，现场必须有人、有物理急停。
2. 定位不可信时**不要发目标**：先看 `tf` 与 `/amcl_pose`，再看地图上机器人位置是否与实际一致。
3. 建图模式下车速默认 0.15 m/s、转向 0.6 rad/s（键盘长按），首次使用请降低速度。
4. 机器人静止时 AMCL 不再"漂移"是正常的；但 TF 过期会让安全闸拒绝导航，这是**设计如此**。
5. 修改任何文件前先 `cp xxx xxx.bak_$(date +%Y%m%d_%H%M%S)`。
