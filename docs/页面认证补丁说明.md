# 页面重新认证补丁说明

> 按你的选择实现：**每次进入 `/console`（配置/导航）或 `/mapping`（建图）都必须重新做人脸验证**。
> 之前的行为是会话保持（机器人上部署的版本 `ttl=None`，认证一次永久有效），所以“进过一次就不用再认证”。

---

## 1. 改了什么

| 文件 | 改动 |
|---|---|
| `scripts/access_gate.py` | 会话增加 `page_used` 标记；新增 `consume_page(token)`：一个会话只允许打开一次受保护页面 |
| `scripts/app.py` | `/console`、`/mapping` 由“检查已登录”改为“消费一次页面许可”；不满足则 302 到 `/?next=<原路径>` |
| `web/login.js` | 验证通过后跳回 `next` 指定页面（支持直接进建图页） |

效果：

```text
打开 /console          → 没认证      → 跳登录页 → 刷脸 → 进 /console
在 /console 里刷新      → 页面许可已用 → 跳登录页 → 刷脸 → 再进
点"进入建图控制"        → /mapping 未认证 → 跳登录页(带 next) → 刷脸 → 直接进 /mapping
页面内 /api/* 轮询      → 会话仍有效，不受影响（不会刷着刷着掉线）
```

陌生人 / 无脸 / 多人：仍然拿不到许可，行为与原来一致。

---

## 2. 怎么应用

机器人开机、与笔记本在同一网络后，在 `D:\课设` 下执行：

```powershell
# 先预览（不改机器人）
.\console\.venv\Scripts\python.exe .\console\apply_page_auth.py --ip 10.224.117.14 --dry-run

# 正式应用（会自动备份 .bak_时间戳、重启 app、做一次 302 验收）
.\console\.venv\Scripts\python.exe .\console\apply_page_auth.py --ip 10.224.117.14
```

看到类似输出即成功：

```text
gate   patched
app    patched
login  patched
已写入 ...
APP_UP
/console 未认证响应: 302 http://127.0.0.1:8765/?next=/console
/ 响应: 200
```

脚本可重复执行：已打过补丁会显示 `already`，不会重复改。

---

## 3. 验证

1. 浏览器打开 `http://127.0.0.1:8765/` → 刷脸 → 进入 `/console`
2. **按 F5 刷新** → 应弹回登录页（这就是新行为）
3. 在 `/console` 点「进入建图控制」→ 弹回登录页 → 刷脸 → 应**直接进入建图页**（不会绕回配置页）

## 5. 已知取舍

- 刷新页面就要重刷脸，演示时请提前说明“这是安全策略”，避免被当成卡住。
- 会话本身仍然不主动过期，但页面许可是一次性的，实质效果就是“每次进入都要验证”。
- 改完必须重启 app；导航栈（move_base/amcl）不用重启。
