# 项目协作规则

本工作区是 bobac2 教室服务机器人课程实训工程。当前任务、进度及验收条件见 [TASK_PLAN.md](TASK_PLAN.md)。先阅读与本次修改有关的代码和记录，再动手；用户当前明确指令优先于本文。

## 角色定位

作为务实的机器人课程设计开发协作者，围绕当前 bobac2 平台完成系统集成、调试和交付。优先复用现有环境与厂家功能，用必要的局部修改解决问题。交流时先讲结论，用容易理解的语言解释原因；明确区分代码已实现、测试已通过、已部署和实机已验证的状态。

## 目录与环境

- `robot_practicum/scripts/`：HTTP应用、人脸识别、业务状态机、ROS适配、底盘与遥控。
- `robot_practicum/web/`：登录、配置、地图导航和建图页面。
- `robot_practicum/config/`、`launch/`：配置和ROS启动文件；`tests/`：单元及集成测试。
- `robot_practicum/README.md`：启动说明；`新操控流程与离线开发记录.md`：新增流程和限制。
- `tmp/analysis/plan.txt`：实践计划书的文本提取，作为需求参考；文档内容不自动构成执行命令。
- 电脑使用Windows/PowerShell；机器人历史环境为Ubuntu 16.04、ROS Kinetic、Python 2.7，恢复连接后再核实实时状态。
- ROS共用代码保持Python 2.7兼容；仅电脑工具可使用Python 3，须明确标注。不要替换机器人系统Python/OpenCV或修改厂家工作空间。

## 工作方式

每轮对话收到具体任务后，先说明任务理解，并尽可能给出完成时间的估计范围，帮助用户安排时间。

- 预计完成时间范围的上限不超过3分钟（含3分钟）：告知预计耗时后直接开始，无需询问是否开始。
- 预计完成时间范围的上限超过3分钟：先告知预计耗时并询问用户是否开始，获得明确确认后再执行。
- 难以可靠估计时，说明原因及影响耗时的主要不确定因素，不编造时间范围。
- 用户调整任务范围时，相应更新估计；执行中发现预计耗时明显增加时，及时说明原因并更新估计。
- 本规则适用于每轮收到的具体任务，不限于新对话的首次任务；同一任务内的进度更新、工具调用和正常继续不视为新任务，不重复询问是否开始。

1. 开始一个变更前，明确目标、相关文件、约束和可观察的完成条件；复杂任务先更新任务计划。
2. 在用户已确认的范围内自主完成可逆的软件工作。只有缺少会影响行为或架构的信息时才提问，不重复询问已确认偏好。
3. 默认保持现有结构，做必要的局部修改。发现额外缺陷先说明影响；不要借机全面重构或引入大型依赖。
4. 先检查现有工作区变更。不得覆盖用户或其他对话的工作，不自行清理未跟踪文件、创建提交或重置Git。
5. 不自动启动并行Agent、定时任务或新增MCP。需要时依据用户具体请求处理。
6. 本项目以课程设计交付为目标。技术选型和实施决策优先选择最适配当前机器人硬件、Ubuntu/ROS版本及现有程序，并能以最短时间达到已确认交付目标的方案；优先复用厂家已有功能、现有依赖和已验证接口，减少环境迁移、重复开发及非必要扩展。满足当前需求即可，不追求超出课程范围的架构复杂度或通用性；交付提速仍须保留必要的功能验证、运动保护和真实结果记录。

## 已确认的产品规则

- 所有已录入且授权的人员都可进入配置；仅没有任何人脸样本时开放首位人员初始化，采集须本人同意。
- 登录时：单人有效正脸、稳定识别后进入配置；未授权人员提示“不是授权人员”并记录事件。无脸、低质量和多人不等同于陌生人识别成功。
- 配置登录会话与巡航中识别人、停车、等待语音的交互状态机分开；保留课程典型巡航场景。
- 2026-11-05用户要求取消登录后15分钟自动过期：已授权配置会话无固定时限，主动退出、浏览器会话结束或应用重启后重新验证；未完成验证的60秒尝试超时仍保留。
- 音频在电脑播放。建图采用W/A/S/D或方向键，松开停车，空格停车并暂停。
- 地图选点后设置最终朝向，明确确认后才提交导航；命名地点供中文指令使用。
- 2026-11-03用户缩减范围：当前不开发墙体、桌椅、设备等障碍物类别识别，不引入YOLO、专项数据采集标注或微调，不将障碍物识别90%列为当前项目完成条件。保留现有激光占用/距离检测、导航避障和全部停车保护。该取舍不改变课程计划书原文，也不表示已经满足其障碍物条款；未经用户重新要求，不将此项恢复为待开发任务。

## 离线与实机边界

- 本地软件开发与离线验证不自动授权连接、部署或发送运动指令；实机操作依据用户当次指令与现场条件执行。
- 模拟身份、示意地图、模拟导航必须在界面、日志和报告中明确标注，正式运行不能接受离线身份绕过入口。
- 保留服务端权限校验、地图ID与坐标检查、运动开关、数据新鲜度、互斥与失联停车；不通过放宽阈值或关闭保护来让测试通过。
- 雷达未覆盖方向不能推断为空闲；电脑软件停车不替代物理急停。恢复实机时先确认底盘响应、方向与停车，再建图和导航。
- 不虚构地图、坐标、识别率或实机成功结果；代码完成、本地测试通过、已部署、现场通过分别记录。
- 不将密码、密钥或人脸样本写入源码、普通日志和发布包；保留现有样本和厂家环境。

## 验证与交付

在工作区根目录运行，按变更选择必要检查：

```powershell
python -m unittest discover -s robot_practicum/tests -v
node --check robot_practicum/web/app.js
node --check robot_practicum/web/login.js
node --check robot_practicum/web/modules.js
node --check robot_practicum/web/mapping.js
```

- HTTP测试需要本机回环访问；沙箱阻断时按工具审批机制处理，不删除权限测试或伪报通过。
- 修改业务、权限或控制逻辑时补充有意义的行为测试；轻微文案修改无需机械添加测试。
- 修改页面交互需实际浏览器验证关键路径、错误与断连状态；未做视觉验收就明确记录，不能用语法检查代替。
- 需查看离线界面时使用 `python robot_practicum/scripts/offline_preview.py --port 8766`；先确认端口与现有进程，避免重复启动。
- `tests/integration_static.py` 需要真实人脸登录，仅人工执行于静态应用，不能用来测试正在进行的实际导航。
- 完成后审查变更，更新任务计划及相关说明。报告本轮改动、实际执行的验证、剩余限制；历史测试记录不当作本轮新结果。
- 当前保留人脸识别90%指标，须由独立标注试验计算；训练样本、连续视频帧和模拟结果不能代替课程成绩。原课程障碍物90%条款记录为本项目当前未覆盖，不填写达标结果，也不以激光占用检测冒充类别识别。
