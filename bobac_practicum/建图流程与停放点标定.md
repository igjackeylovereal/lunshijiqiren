## 已修复的问题

厂家 `odometry.cpp` 只在 `/real_vel` 回调里更新 `current_time`，循环可能重复发布旧时间戳。厂家运动学节点又会重复发布缓存的 `/real_vel`，不能仅凭该话题有数据判断实际底盘仍在线。

新工程的 `wheel_odometry.py` 直接订阅实际 `/car_data` 轮速反馈，按已核对的厂家轮速符号计算两轮差速里程计，每次有效反馈使用新时间戳。没有真实反馈就不发布 `/odom` 或其 TF；反馈间隔超过0.5秒或时钟回跳时停止积分并锁定故障，检查后需要重启该节点，防止把失联期间当成正常位移。

厂家源码保持原样。新 `mapping.launch` 和 `navigation.launch` 已接入此里程计，默认 `start_base=false`、`start_lidar=false`、`allow_wheel_commands=false`。单独启用底盘反馈时，默认电机指令订阅重映射到无发布者的隔离话题；仅显式允许轮子指令时才启动厂家运动学指令节点。本次没有启动这个底盘入口。

厂家运动学节点会保留最后一条速度，因此新入口增加 `velocity_watchdog.py`：只在允许轮子指令时运行，指令超过0.3秒未更新就持续发布零速给专用中间话题，再由厂家运动学节点转换为电机指令。未收到指令、无效值或时钟回跳时均归零；它不在本次静态检查中启动。

轮径0.068米、轮距0.32374米以及雷达安装位置来自厂家配置/URDF，仍是未实测校准的名义值。

## 现在可以执行的集中指令

```bash
# 默认只读检查：不会启动底盘或轮子指令
bash ~/bobac_practicum_ws/src/bobac_practicum/scripts/mapping_commands.sh

# 如雷达已运行会直接退出，避免重复打开同一串口
bash ~/bobac_practicum_ws/src/bobac_practicum/scripts/mapping_commands.sh lidar-only

# 查看实际雷达；5秒后结束统计
source /opt/ros/kinetic/setup.bash
source ~/bobac2_ws/devel/setup.bash
source ~/bobac_practicum_ws/devel/setup.bash
timeout 5 rostopic hz /scan

# 检查实际建图输入；当前尚无实际里程计，超时是待完成项
timeout 3 rostopic echo -n 1 /car_data
timeout 3 rostopic echo -n 1 /odom/header
timeout 3 rosrun tf tf_echo odom base_footprint
```

需要复现隔离链路时，执行以下命令，结束后按 Ctrl+C。它不提供真实里程计，不发布实际 `/map`，也不建立停放点：

```bash
bash ~/bobac_practicum_ws/src/bobac_practicum/scripts/mapping_commands.sh isolated-check
```

## 后续正式采图：当前不执行

正式采图前，先接通真实底盘反馈，验证轮速符号、轮径轮距、时间戳与 `odom → base_footprint → laser_rada_Link`，确认地图中的运动方向和实物一致。

只有后续明确允许机器人移动时，才使用下面的硬件采图入口。若雷达已在运行，保持 `start_lidar:=false`；否则改成 true。该命令会打开轮子指令链，本次没有执行：

```bash
source /opt/ros/kinetic/setup.bash
source ~/bobac2_ws/devel/setup.bash
source ~/bobac_practicum_ws/devel/setup.bash
roslaunch bobac_practicum mapping.launch \
  start_base:=true start_lidar:=false allow_wheel_commands:=true
```

通过已经验证的手柄或其他人工遥控缓慢采集教室外圈、门口及可通行主通道，最后回到起点检查闭环。此阶段不需要向导航 Action 发送目标点。观察墙体是否重影、转弯是否错位、主要区域是否仍有大片未知；仅原地扫描不能证明整间教室建图完成。

地图检查通过后，在另一个已加载 ROS 环境的终端保存：

```bash
mkdir -p ~/bobac_practicum_run/maps
map_prefix="$HOME/bobac_practicum_run/maps/classroom_$(date +%Y%m%d_%H%M%S)"
rosrun map_server map_saver -f "$map_prefix" map:=/map
ls -l "$map_prefix.pgm" "$map_prefix.yaml"
```

PGM和YAML必须配套保留，YAML里的 `image` 路径须能访问。移动文件后先检查该路径再重载。停止 Gmapping 后再加载保存地图，避免两个节点同时发布 `/map`。

## 有图后再标定停放点

1. 加载实际教室地图，接入真实里程计及雷达，启动定位；先验证激光轮廓与地图墙体对应。
2. 由你指出固定停放区域，并确定机器人停靠后的朝向。目标应是可通行空地，不能仅凭“教室”二字自动选择房间中心。
3. 若采用当前位姿记录法，先让机器人实际位于指定停放点并定位稳定，再在页面记录当前实际位置，得到地图坐标 `x、y、yaw` 和 `map_id`。
4. 如果采用在地图上指定点的方法，另行核对地图像素到米制坐标的转换、朝向与障碍物间距；它不是点击地图任意位置就立即开车过去。
5. 固定点与该地图版本绑定；重建地图后重新确认。之后才进入真实导航、停车和到达精度测试。
