# 人脸识别修复与静态验证

日期：2026-11-03。SSH 已恢复，声音继续通过电脑播放器输出，机器人保持静态模式。

## 原因与处理

| 原因 | 现场证据 | 处理 |
| --- | --- | --- |
| 旧 Haar 检测器漏检 | 画面有人，但旧检测器连续采样未检出；同一画面增强对比度后才检出 | 换为 OpenCV SSD ResNet-10；后备检测增加 CLAHE |
| 脸部受侧光影响偏暗 | 录入时脸部平均亮度约 35～39 | 调整相机亮度、gamma 和背光补偿；保留原参数供恢复 |
| LBPH 对当前距离、角度及光照变化敏感 | 完成补录后，LBPH 距离仍常在阈值 60 上下波动 | 改用 OpenFace 128 维特征；复用已有灰度样本，统一实时与模板预处理 |
| 连续帧计数易被单帧波动打断 | 原程序要求连续 5 帧匹配 | 最近 6 个有效帧中当前候选至少匹配 4 帧；过期帧、无脸和多人不累计 |
| 短暂丢脸后恢复被冷却阻塞 | 画面候选已匹配，但状态仍无授权人员 | 撤销身份时清除该身份的旧冷却记录，重新稳定匹配可立即恢复 |
| 多人时缺少画框提示 | 画面被判多人，界面却无法指出额外人脸 | 为所有检出的人脸显示框与编号，多人仍不授权 |

ROS 自带 OpenCV 3.3.1-dev 的 DNN 推理在实机报错，因此视觉模型在私有 OpenCV 3.4.2 子进程运行，原 ROS 环境和厂家代码保持原样。新模型来源、校验值与许可见 `assets/MODELS.md`。

## 最终配置

- 孟熙恒（p001）90 张样本：原 30 张，两次经本人同意各补录 30 张；其余三位未录入。
- 特征相似度阈值 0.82；多类别领先差至少 0.08；对同一人最相近 3 个模板的相似度取平均。
- 陌生人初测在 0.75 阈值下出现过单帧候选波动，未形成该窗口内的实际授权；之后阈值收紧至 0.82。没有为提高通过率放宽阈值。
- 相机控制：`brightness=12,gamma=140,backlight_compensation=2`。原值记录于机器人运行目录的 `camera_controls_before.txt`。
- 人脸过暗、过亮、模糊、过小、贴边或多人时不采样/不授权。补录增加间隔与重复样本过滤，并显示分阶段提示。
- 视觉计算在机器人本地；陌生人测试只做实时处理及数值记录，没有保存陌生人测试照片。

## 本次验证结果与限制

最终阈值下，本人重新入镜的 12 秒测试共有 55 帧，其中 26 帧为合格单人画面，26 帧全部候选匹配，相似度约 0.904～0.966，触发 1 次真实授权事件。其余 29 帧检测到多人，按规则阻止/撤销授权。画面背景仍会影响能否进入交互，需留意红色人脸框。

最终未录入同学的短时复测取得 11 个合格单人帧，相似度约 0.533～0.726，候选匹配为 0，授权事件为 0。该轮合格单人帧数量不足，保留“需补充独立陌生人试验”的结论。

机器人 Python 2.7 上 42 项单元测试通过；相机 JPEG、PC 语音 WAV、录入同意校验、跨来源请求拒绝和缺少地图时阻止虚构目标点等接口检查通过。电脑侧也验证 SSH 隧道能读取语音，配置为 PC 输出。

这些连续帧仅用于工程排查，不能当作独立人脸准确率试验。课程“正常光照、正面拍摄不低于 90%”仍需多轮独立入场、四位授权人员及未录入人员试验统计。`validation_report.json` 中两个课程准确率仍为空。

## 继续使用

1. 打开 `http://127.0.0.1:8765/` 并刷新。点击“在电脑扬声器播放回复”解锁浏览器音频。
2. 单人正对相机，额头和下巴完整入镜；尽量面向光源。看“特征相似度”，不要把后备 LBPH 距离或相似度当成准确率。
3. 多人时看红框，其他人需退出相机画面；本次未改变多人不授权规则。
4. 需要继续验证时，使用 README 的 `face_trial.py` 命令记录单次实测；独立验收使用 `evaluate.py` 汇总。
5. 导航准备与待办见 `导航静态准备.md`，当前不启动底盘或真实导航。
